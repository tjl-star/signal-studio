# 人人视频运营数据看板 V1

当前版本保持原有静态页面和业务结构，数据入口已由 Mock 数据切换为 Quick BI 真实数据快照。

## 运行

```powershell
cd dashboard-demo
python -m http.server 8000
```

浏览器访问 `http://localhost:8000`。页面通过 `fetch` 读取 `real-data.json`，不要直接双击 `index.html`。

## 数据文件

- `real-data.json`：页面当前使用的真实数据快照。
- `mock-data.json`：历史 Demo 参考文件，页面不再读取。
- 快照日期：`2026-07-29`（Asia/Shanghai）。
- 来源：Quick BI「人人视频数据总览」。
- 默认查询范围：全应用、全客户端、全设备、全地域。

## 已接入数据

- 首页：账号 DAU、新增用户数、一日留存、三日留存、播放人数、播放次数、人均播放次数。
- 首页计算字段：播放率 = 播放人数 / DAU。
- 内容运营：剧集榜单系列名 TOP30 的排名、剧名、播放次数、国别、昨日变化和新入榜。
- 内容运营：TOP30 中 28 条已取得播放设备数，并映射为 `play_uv`。

## 字段状态

- `confirmed`：已经从 Quick BI 对应日期和口径直接核验。
- `calculated`：仅使用已确认的依赖字段按数据模型公式计算。
- `pending`：接口结果尚未取得或字段口径无法验证；值保持 `null`，页面显示“后续补充”。

本快照中仍为 pending 的主要字段包括：人均播放时长、榜单中未进入播放设备数 TOP30 的两条 `play_uv`、内容类型、题材，以及搜索、流量和推荐模块。

留存数据来自「基础数据 → 留存分析 → 新账号留存 → 用户日留存」的 2026-07-29 页面展示值。播放汇总来自「播放数据 → 播放数据(20220731后不含新人人)」同日总值。榜单昨日变化使用 2026-07-29 与 2026-07-28 的系列名 TOP30 播放次数计算。

## 数据接入原则

- Quick BI 原始字段先映射到现有 JSON 数据模型，页面不直接消费原始响应。
- 不用 Mock 值回填真实数据缺口。
- 不可验证的数据不推断、不模糊关联，统一保留 `null` 和 `pending`。
- 当前为静态快照，不包含后端、部署、定时任务或自动登录。
