# Signal Studio 面试演示流程

## 3分钟版本

1. **运营总览（30秒）**：说明监测3个竞品频道，展示总体播放、互动率、48小时新内容和高潜Top内容。
2. **竞品视频库（45秒）**：按内容类型和影视项目筛选，打开单条视频，展示当前指标、指标历史、分类依据与YouTube原链接。
3. **影视项目情报库（35秒）**：说明如何把YouTube内容与TMDb项目连接，查看类型、国家、语言、演员、评分和频道覆盖。
4. **AI选题助手（50秒）**：选择1—5条竞品证据，生成Brief；重点展示事实、运营假设、标题、时长、标签、发布时间建议、风险和数据缺口。
5. **数据与任务（20秒）**：展示本地采集、任务记录、脱敏日志和CSV/Markdown导出，强调公开版不暴露密钥或写操作。

## 建议讲法

> 我没有把这个作品做成一次性爬虫。YouTube handle先转换为频道资源，再取得上传播放列表和视频ID，最后批量查询统计数据；原始JSON按时间戳留档。清洗后以platform和video_id为唯一键Upsert到SQLite，每次运行追加指标历史。TMDb负责补充影视语境，FastAPI统一向React提供业务接口。AI模块只接收可追溯的数据证据，明确区分事实、运营假设、风险与数据缺口。

## 面试官可能追问

- **为什么不用网页爬虫？** 官方API更稳定、字段清晰、合规风险更低；只有官方API或导出无法满足时才评估公开网页采集。
- **为什么使用人工映射？** 首版用人工审核保证影视实体准确，避免仅靠标题NLP把演员、节目和剧名误关联；后续可加入候选匹配与审核队列。
- **热度分是官方指标吗？** 不是，它是用于内部排序的运营指标，页面和README均明确口径。
- **AI会不会编数据？** 模型只能使用结构化证据，事实绑定视频ID，缺失信息必须列为数据缺口；失败时使用明确标记的规则回退。
- **如何扩展更多平台？** 统一为raw留档、clean标准字段、SQLite平台联合键、指标历史和数据源适配器，再复用分析和前端接口。
