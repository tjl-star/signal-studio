# 运营月报数据展示规范

## 1. 文档目的

本规范用于定义运营月报展示什么数据、采用什么统计周期、使用哪些业务维度，以及各看板 Tab 的内容如何进入月报正文。

月报服务运营与管理层，重点回答四个问题：

1. 用户规模是否变化；
2. 用户是否产生有效播放消费；
3. 哪些内容和剧种贡献了播放；
4. 搜索、首页和资源位是否有效承接用户需求。

月报采用正式白纸报告风格，更像经营报告，少像 BI 数据看板。

## 2. 总体展示原则

- 不使用大量 KPI 卡片堆叠。
- 每章只保留 3～5 条有业务意义的事实。
- 每个指标只设置一个主要展示位置，避免在摘要、KPI 卡片和图表中重复出现。
- 趋势使用折线图，排名使用横向条形图，结构使用排序条形图，链路使用漏斗。
- 没有可靠数据、没有可比基准或无法解释的数据不展示。
- 月报只展示环比，不纳入同比字段。
- 日粒度数据用于趋势，月粒度数据用于汇总。
- 不修改数据接口、指标口径、数据获取逻辑或 PDF 导出逻辑。

## 3. 第一章：月度整体表现

### 3.1 建议展示的核心数据

#### 月均设备 DAU

- 统计粒度：每日 `device_dau` 汇总为自然月日均值。
- 数据口径：`coreData.device_dau`，是设备口径，不称为账号 DAU。
- 业务意义：反映整个月的平均活跃规模，比单日快照更适合月报。
- “月末设备 DAU”仅表示最后一个有效日期的设备 DAU，不代表整月活跃规模，不作为默认月度指标。
- 若月内出现明显峰值、低谷或异常，再保留 DAU 日趋势图；若走势平稳则不展示趋势图。

#### 月累计新增设备

- 统计粒度：每日 `new_device` 汇总为自然月累计值。
- 数据口径：`coreData.new_device`。
- 业务意义：反映当月拉新规模。

#### 月度播放消费规模

- 优先使用数据源提供的月度播放汇总。
- 可展示播放 UV 和播放 VV，但必须保留 UV、VV 的原始含义。
- 若只有内容明细，未确认聚合口径前，不直接手工汇总为整体播放量。

#### 人均播放时长

- 优先使用 `perCapitaWatchDuration` 返回的月度汇总行。
- 若只有日粒度数据，则展示日趋势或不展示单一月度值。
- 不直接对每日人均时长做简单平均，除非该聚合口径已被数据源确认。

#### 播放率或人均播放次数

- 二者只选一个进入第一章，避免消费深度指标重复。
- 播放率优先使用源端汇总值；没有可靠月度口径时不自行计算。
- 选择人均播放次数时使用 `perCapitaPlayCount` 的源端结果。

### 3.2 第一章页面形式

- 删除 5 张 KPI 卡片。
- 使用 3～5 条完整事实句，格式为“指标值 + 环比变化”。
- 环比默认比较本月完整周期与上月完整周期。
- 不完整月份按相同已过去天数比较，并标注“截至 YYYY-MM-DD”。
- 不展示 MAU。当前已核验数据只有每日设备 DAU，没有可靠的月度去重用户/设备 MAU。
- 如果保留 DAU 趋势图，则不再单独用摘要重复表达同一 DAU 趋势结论。

### 3.3 第一章事实句示例

> 本月月均设备 DAU 为 X，较上月同期上升/下降 Y%。

> 本月累计新增设备为 X，较上月同期上升/下降 Y%。

> 本月播放消费规模为 X 播放 VV，较上月上升/下降 Y%。

> 本月人均播放时长为 X 分钟，较上月上升/下降 Y%。

## 4. 各 Tab 在月报中的内容

| 看板 Tab | 月报正文展示 | 维度与粒度 | 展示方式 |
|---|---|---|---|
| 运营总览 | 本月最值得关注的规模、内容、搜索和入口变化 | 月度、全局；仅保留有证据的变化 | 事实句 |
| 核心数据 | 月均设备 DAU、新增设备、消费深度 | 天/月；必要时拆分安卓、iOS、M 站 | 摘要或条件性趋势图 |
| 热播榜单 | 播放贡献最高的内容 | 月度、剧集/电影；Top10 | 横向排名图 |
| 热搜榜单 | 搜索热度最高的词条或内容 | 月度、搜索词/剧名；Top5～Top10 | 少量事实对照 |
| BL 内容消费 | BL 内容是否形成显著播放贡献 | 月度、内容、剧种、客户端 | 仅在贡献明显时展示 |
| 剧种内容贡献 | 各剧种播放结构 | 月度、剧种；按播放 VV 或占比排序 | 排序条形图 |
| 播放增长榜 | 播放增长明显或新入榜内容 | 月度、内容；必须有可靠环比基准 | 横向排名图或事实句 |
| 首页频道 | 频道点击到有效播放的承接结果 | 月度、客户端、频道 | 频道排名图或事实句 |
| 猜你喜欢 | 推荐入口点击、曝光和播放转化中的关键结果 | Quick BI 专属口径、客户端、日期 | 1～2 条事实 |
| 首页板块 | 高点击、高点击率或明显变化的板块 | 固定客户端、频道、板块/子板块 | Top/异常事实 |
| 搜索漏斗 | 搜索完成、影视点击、起播、5 分钟播放及核心转化率 | 月度、Quick BI“搜索整体数据”同一组件 | 简化漏斗或事实句 |
| Banner 点击 | 高点击量或高点击率资源位 | 客户端、位置、标题；应用曝光门槛 | 横向排名图 |
| 弹窗数据 | 有效播放贡献高或转化效果明显的组件 | 安卓新人人、组件、日期 | Top3 事实或横向排名图 |

看板 Tab 继续保留日常分析、筛选、排序和明细表；月报只抽取可形成经营判断的结果，不复制全部明细。

## 5. 各业务章节的详细规范

### 5.1 内容侧

#### 热播内容

- 主指标：报告周期播放 VV，必要时补充播放 UV。
- 维度：内容名称、剧集/电影类型、剧种、题材标签。
- 范围：真实返回的 Top10，不补造缺失记录。
- 图形：播放 VV Top10 横向排名图。
- 不在月报中重复展示完整 Top30 明细，明细留在热播榜单 Tab。

#### 剧种结构

- 主指标：剧种播放 VV 或播放 VV 占比。
- 维度：剧种。
- 排序：按指标值降序。
- 图形：排序条形图，不使用无比较价值的装饰性图形。

#### 播放增长

- 仅在存在可靠上月或前一周期基准时展示增长榜。
- 需同时保留内容名称、当前播放值和增长变化。
- 小样本极端变化、无基准记录和缺失记录不进入月报结论。

#### BL 内容消费

- 作为专项内容观察，不默认占用月报主体篇幅。
- 只有当 BL 内容对整体播放贡献明显，或出现显著增长/下降时，才展示事实句或 Top 排名。
- 必须明确内容、剧种、客户端和用户类型口径。

### 5.2 用户主动需求

#### 热搜

- 展示搜索 UV 或搜索 VV 最高的 Top5～Top10。
- 维度：搜索词/剧名、内容类型、剧种、题材。
- 搜索词榜和剧集热搜榜分开处理，不能互相替代。
- 热搜与热播的关系只保留少量事实，例如“Top10 重合 X 个内容”，不得由搜索热度直接推断播放增长。

#### 搜索漏斗

- 关键阶段：进入搜索页、搜索完成、影视点击、详情页起播、播放 5 分钟。
- 关键结果：搜索完成率、首帧转化率、5 分钟转化率。
- 所有阶段和转化率必须来自 Quick BI“搜索整体数据”同一组件，不能与 `dramaConversion` 拼接。
- 月报只保留链路中最能说明损耗的结果，完整漏斗留在搜索漏斗 Tab。

### 5.3 首页运营

#### 首页频道

- 关注频道入口点击、内容点击、详情尝试播放、5 分钟播放和有效播放的承接。
- 维度：客户端、频道、自然月。
- 以有效播放 UV 或关键转化率进行频道比较。
- 当前固定口径为 `android_rrsp_xb` 时，月报必须保留该客户端说明。

#### 猜你喜欢

- 仅展示对运营有意义的结果，例如推荐入口点击规模、内容点击转化、首帧/播放/5 分钟转化或人均播放时长。
- 使用 Quick BI“首页数据”专属口径，不能用 `dramaConversion` 替代。
- 不把每个漏斗阶段都做成 KPI 卡片。

#### 首页板块

- 关注高曝光、高点击、高点击率和明显变化的板块。
- 维度：固定客户端、频道、板块/子板块。
- 异常数据保留在明细，但不参与月报排行；异常包括点击 UV 大于曝光 UV、点击率超过 100% 等。

### 5.4 资源位运营

#### Banner

- 展示点击 UV Top 或点击率 Top，优先保留有足够曝光量的记录。
- 维度：客户端、Banner 位置、Banner 标题。
- 必须保留曝光门槛，避免低样本点击率制造错误结论。
- 不用点击 UV 替代跳转播放 UV 或有效播放 UV。

#### 弹窗

- 重点展示有效播放 UV、跳转播放 UV、点击率或转化率中的有效结果。
- 维度：安卓新人人、组件名称、组件 ID、自然月。
- 默认只展示 Top3 或显著变化组件。
- 超过 100% 的异常率保留并标注异常，不擅自修正原始数据。

## 6. 统一维度与比较规则

### 时间

- 默认使用自然月。
- 未完成月份标注“截至 YYYY-MM-DD”。
- 日粒度数据用于趋势，月粒度数据用于汇总。
- 不同模块日期覆盖不一致时分别标注，不能把旧日期数据改标为当前月份。

### 客户端与用户类型

- 大盘默认全客户端；只有在发现明显差异时才拆分安卓、iOS、M 站。
- 页面专属模块必须保留原有客户端、应用 ID 和风险筛选。
- 设备 DAU 不得称为账号 DAU。
- 新用户、老用户、新设备、老设备不能混用。

### 内容

- 沿用原始内容名称、内容类型、剧种和题材标签。
- 榜单保留接口原始排名，不在前端重新定义排名。
- 同名内容是否合并遵循当前看板映射规则。
- Top 榜只展示接口真实返回范围。

### 运营入口

- 首页频道：频道。
- 首页板块：频道、板块、子板块。
- Banner：客户端、位置、标题。
- 弹窗：组件名称、组件 ID。
- 搜索：搜索词、剧名、内容类型、剧种、题材。

## 7. 数据源与字段要求

| 业务内容 | 数据源/接口或组件 | 原始字段 |
|---|---|---|
| 日活设备 | data_provider / `coreData` | `device_dau` |
| 新增设备 | data_provider / `coreData` | `new_device` |
| 播放率 | data_provider / `coreData` | `play_rate` |
| 人均播放时长 | data_provider / `perCapitaWatchDuration` | 总人均观看时长字段 |
| 人均播放次数 | data_provider / `perCapitaPlayCount` | 总人均播放次数字段 |
| 内容播放 | data_provider / `seasonPlayVV` | `play_uv`、`play_count` |
| 热搜 | data_provider / `seasonSearchAuthInfo` | `search_uv`、`search_cnt`、`drama_type`、`plot_type`、`season_type` |
| 首页频道 | data_provider / `dramaConversion` | 原始 UV 与转化字段 |
| 搜索漏斗 | Quick BI“搜索整体数据” | 同一组件返回的搜索阶段 UV 与转化率 |
| 猜你喜欢 | Quick BI“首页数据” | 页面专属推荐入口字段 |
| Banner | Banner 页面组件或 `bannerClickData` | 曝光、点击、CTR 字段 |
| 弹窗 | 弹窗页面组件或 `popupWindowData` | `expost_uv`、`click_uv`、`jump_uv`、`play_uv`、`ctr`、`conversion_rate` |
| 留存 | Quick BI 留存页面 | 1 留率、3 留率及 cohort/date |

任何进入月报的数字都必须能够追溯到来源、接口/组件、原始字段、数据日期、客户端/平台、用户口径和筛选条件。

## 8. 不展示内容

- 无可靠月度去重来源的 MAU。
- 无法确认月度聚合口径的单值播放率、人均时长或人均次数。
- 没有有效比较基准的同比、环比或增长结论。
- 低曝光样本导致的极端点击率。
- 以热搜替代播放，以点击 UV 替代跳转播放/有效播放。
- 旧日期数据伪装成当前月份数据。
- 仅为填满版面而增加的 KPI 卡、装饰性图表和完整明细表。

## 9. 验收标准

- 第一章无 KPI 卡片。
- 第一章摘要不含同比字段。
- 每条事实句包含指标值、统计周期和环比状态。
- “月末设备 DAU”不再被当作整月活跃规模。
- 无可靠来源时不展示 MAU。
- Top 内容使用横向排名图，剧种结构使用排序条形图。
- 热搜、Banner、弹窗只保留少量有业务意义的结果。
- 指标来源、原始字段、日期和筛选口径可追溯。
- 本规范不要求修改数据接口、数据逻辑、PDF 导出逻辑或其他非月报页面。
